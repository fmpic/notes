## 最短入门路线

1. 打开 KV cache calculator，先估算容量。
2. 跑 local CPU offload，确认第二次相同前缀命中。
3. 跑 online session，量化 cold/hit TTFT。
4. 用 `chunk_statistics` 验证自己的数据是否真的有复用。
5. 用 `disagg_prefill_mp` 理解独立 server 和 1P1D。
6. 再按环境选择 P2P、远端 L2、Kubernetes 或插件开发。

## 高风险与常见误区

- `rust_backend_offload.py --disk_path=/dev/...` 可能擦除设备，必须使用专用测试盘。
- direct NIXL PD/P2P 需要高带宽互联；普通网络可能让传输开销大于收益。
- centralized sharing 必须让所有进程使用一致 `PYTHONHASHSEED`。
- `examples/multi_process/` 是 raw 参考 YAML；当前生产 Operator 使用不同的 HostIPC/node-local Service 模型。
- `blend_kv/` 是 legacy；`blend_kv_v1/` 需要 ad-hoc vLLM 修改；当前 MP CacheBlend 是 V3/Operator plugin 路径。
- `disagg_prefill_mp` README 明确说明示例仅 1P1D 且未针对性能优化。
- remote storage 示例需要对应 SDK、服务、凭据和网络，不应把 connector 初始化成功等同于数据已持久化。
- Mamba/GDN、MUSA、HPU、multi-server DP/PP 等有明确功能子集，见 [限制清单](08-source-coverage.md#当前明确限制)。
